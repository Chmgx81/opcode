Security

The sandbox

Every shell command the model runs executes under a Linux kernel sandbox: Landlock confines the filesystem — reads anywhere, writes confined to the project directory, /tmp, and language dev caches — and a hand-written seccomp filter blocks network sockets (x86_64). The sandbox fails closed: if any rule cannot be applied, the command does not run. On macOS and Windows the file confinement applies and commands are gated by prompts instead.

The permission gate

Every tool call passes a permission decision before it runs. The dialog shows the literal command, No is never preselected, and "don't ask again" grants are canonicalized and fail closed on metacharacters — never wider than what the dialog showed. Grant rules cover flags written either way (--yes/-y) and deliberately refuse to merge pairs that differ across tools (--all/-a is --text in grep).

Secrets

Keys live in ~/.opcode/auth.json, 0600, never in a project directory. Every key in the process is registered with a redactor that scrubs it from tool output, error text, the audit log, and session saves. Reads and writes of the credentials file are denied at every layer, checked on the opened descriptor by inode — a sandboxed command cannot swap a symlink in under the check. !command secret-manager values resolve only from the user-level file, with a 10-second timeout, and their output is never displayed.

Untrusted text

Everything the model or a tool produced — streamed text, reasoning, tool arguments, results, subagent output, session previews — passes a display-boundary sanitizer that strips terminal escape sequences before it can reach your terminal. Model-provided instructions in project files are fenced as data in the system prompt; project-level skills only load after you trust the project.

What opcode deliberately does not do

  • No telemetry. One optional update check (a version compare against the latest release tag), off with one env var.
  • No background downloads; opcode update runs only when you type it, and verifies a sha256 before extracting.
  • Release integrity is checksums, not signatures — verified in transit, trusting the GitHub account. Enable 2FA.
  • MCP servers run unsandboxed by design and are gated behind project trust; their environment is scrubbed to an allowlist.
