Usage

Modes

Three permission postures, cycled with tab / shift+tab, or picked with /mode:

ModeWhat runs without asking
⎕ planRead-only tools; every write, command, or fetch proposes a plan you approve.
› build (default)Sandboxed commands and in-tree writes run free; anything else asks.
⏭⏭ full-autoEverything proceeds without asking — the sandbox still confines writes to the project directory, /tmp, and dev caches.

Permission dialogs

An action outside the mode's bounds opens a dialog: the literal command in plain words, the tier it belongs to, three options — Yes, Yes, and don't ask again for (a session-scoped prefix rule, never wider than what the dialog showed), and No. Nothing is preselected. For 400ms after a dialog opens, keystrokes are swallowed — a fast typist's stray "y" must not answer an approval they never read.

Commands

/help /models /model /mode /sessions /skills /mcp /theme /diff /login /logout /doctor /update /exit /quit — an unknown command errors in place with the closest match; it never becomes a billed model turn.

Sessions

The session file rewrites atomically at every turn boundary, so a crash loses at most the turn in flight. opcode --continue resumes the newest readable session (a damaged newest file is skipped and named); /sessions lists them all. Resuming grows that session's own file. Compaction keeps the context bounded when context_window is configured — the working line reads it as context 62%.
