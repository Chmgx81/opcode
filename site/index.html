Why opcode

Safe by default, provider-agnostic, honest about it.

◉Sandboxed by default

Shell commands run in a kernel sandbox — Landlock confines the filesystem, seccomp blocks network sockets. Writes outside the project ask first; reads of your credentials never run.

◉Any provider, your key

Fifteen providers built in — OpenRouter, Anthropic, OpenAI, Mistral, Google, Groq, Ollama, and more — switched live at runtime. Keys are stored 0600 and never leave your machine.

◉One binary, no account

No runtime, no plugin stack, no subscription, no telemetry. One optional update check you can turn off with one environment variable. Open source, MIT.

Features

Plan the work, delegate it, watch it land.

Plan mode

Research first, act on approval. In plan mode the agent works read-only; when a change is warranted it presents a plan and waits. One keypress switches the session into acting — y to implement with every action still asking, a to implement with auto-accept. The approval is honest about what it grants, and the mode is visible on the footer at all times, colored by what it means.

Subagents

Delegate a focused task — a bounded scope, its own rounds, its own budget — to a second agent running the same tools under the same permission gate. Progress renders as labeled lines in the transcript; the result comes back as one block. Subagents are bounded by round caps and a watchdog, inherit cancellation, and cannot recurse.

◉A permission gate that shows its work

The literal command on the dialog, No never preselected, and "don't ask again" grants that are never wider than what the dialog showed.

◉Sessions that survive

The session file rewrites atomically at every turn boundary — a crash loses the turn in flight, never the conversation. Resume with --continue or browse /sessions.

◉Live task list & context readout

A todo panel tracks multi-step work, and the working line reads the context window when it is configured — context 62% before compaction ever surprises you.

First run

The setup is the UI.

No files to edit. Run opcode in a project directory: the provider picker is already open. Pick a provider, paste its key (masked, stored 0600 in auth.json), and its live model list opens by itself — key → models → pick, with no command to remember in between. /model is the hub any time: your pinned models, providers you hold keys for, and keyless ones one /login away.

FAQ

Questions people actually ask.

Do I need an account or a subscription?
No. opcode talks to your provider with your key. There is nothing to sign up for and nothing to pay us — you pay your provider, as always.
Does it phone home?
One update check at startup (at most daily, three-second cap, silent when offline) that compares the running version against the latest release tag. OPCODE_NO_UPDATE_CHECK=1 or "update_checks": false turns it off. That is the only request opcode makes on its own.
What happens if the model tries to run something dangerous?
In build mode (the default), sandboxed commands and in-tree writes run free; anything touching outside the project opens a permission dialog showing the literal command. Nothing is preselected, and grants are never wider than what the dialog showed.
Which platforms?
Linux, macOS, and Windows binaries for every release. The kernel sandbox is Linux-only (Landlock 5.13+); elsewhere the file confinement applies and commands are gated by prompts.
Can I use it in CI or scripts?
Yes — opcode -p "prompt" runs one headless turn; --json emits one JSON event per line. Use full-auto for unattended runs; permissions fail closed with nobody to ask.
Where do my sessions and keys live?
~/.opcode/ — sessions in sessions/, keys in auth.json (0600), config in config.json. Nothing is written to a project directory except the work you asked for.
